# Проверочный лист безопасности для бизнес-систем PropDevelopment

### Выбор разделов и обоснование
Разделы выбраны по двум глобальным проблемам компании (нарушен контроль данных, небезопасные API партнёров) и по четырём потребностям бизнеса (жалобы клиентов на чужие данные, реакция на утечки, развитие сервисов на данных, соответствие законодательству РФ). Дополнительные темы (API партнёров, ПДн и законодательство, организация ИБ) добавлены в максимально подходящие разделы шаблона.

| Раздел | Решение | Обоснование |
|---|---|---|
| I. Управление доступом | Включён: 14 вопросов шаблона и 3 добавленных | Нет ограничений на доступ к данным, партнёр одной УК видит данные другой, клиент видит в кабинете чужое ФИО, учётные записи разнесены по нескольким системам. Сюда же добавлены вопросы о единых политиках безопасности и изоляции данных API партнёров и об изоляции данных клиентов в личном кабинете. |
| II. Безопасность данных | Включён: 14 вопросов шаблона и 5 добавленных | Это ключевая проблема компании. Добавлены вопросы о контроле потоков между продуктами, едином источнике правды о клиенте, реестре и минимизации данных в API партнёров, а также о мониторинге данных, передаваемых партнёрам. |
| III. Управление инцидентами | Включён: 6 вопросов шаблона и 5 добавленных | Недавняя утечка у конкурента, SIEM не выявлен, жалобы клиентов не оформлены как инциденты. Сюда же добавлены организационные вопросы: оценка соответствия законодательству, проверка безопасности новых интеграций, участие специалиста ИБ в решениях, обмен информацией между командами, роль отвественного за ИБ (один специалист на всю компанию, процесс передачи информации нарушен). |
| Защита инфраструктуры (раздел шаблона) | Не включён | Ни одна из проблем и потребностей бизнеса не сводится к сетевой защите: утечки и чужие данные в кабинете вызваны отсутствием ограничений доступа и контроля данных и API (разделы I и II), а не взломом периметра. Периметр для клиентов и собственников уже закрыт firewall, это учтено в вопросе I.10. Сегментация и замкнутые контуры покрыты вопросом I.9, мониторинг аномалий и SIEM вопросами II.19 и III.1. По остальным пунктам данных в описании нет. |
| Специфические аспекты: общие вопросы | Не включён | MDM, VPN, контроль неавторизованных устройств и облачные резервные копии не связаны с проблемами компании. Мобильное приложение предназначено для внешних собственников, а не для корпоративных устройств, резервное копирование уже проверяется в разделе II. |
| Специфические аспекты: управление оборудованием и физической безопасностью | Не включён | Проблемы компании находятся на уровне логического доступа, потоков данных и API, а не физической защиты. Данных о ЦОД в описании также нет. |

| 10. | Ограничен ли доступ к системам из внешних источников? | Частично | Клиенты и собственники попадают в систему через firewall. Партнёры УК и платёжная система подключаются по API без единых политик безопасности. |
| 11. | Ведётся ли единый реестр учётных записей? | Нет | По схеме учётные записи разнесены: auth-db-1 для покупателей, отдельный auth-db-1 в финансовом домене, два экземпляра Active Directory. Единого реестра не показано. |
| 12. | Используются ли средства управления учётными записями на базе единого реестра? | Нет | Следствие п.11: единого реестра нет. |
| 13. | Применяются ли средства для отзыва прав доступа? |  | Недостаточно данных. |
| 14. | Используются ли средства централизованного контроля доступа? | Нет | Контроль разрознен: два экземпляра AD и отдельные Keycloak, единой точки управления доступом нет. |
| 15. | Действуют ли единые политики безопасности для API партнёров (аутентификация, авторизация, ограничение запросов)? | Нет | Прямо указано: системы используют API управляющих компаний без единых политик безопасности. |
| 16. | Проверяется ли при каждом запросе принадлежность данных партнёру (изоляция данных между управляющими компаниями)? | Нет | Выявлены случаи, когда партнёр одной УК видит или изменяет данные клиентов и жилых комплексов другой УК. |
| 17. | Исключено ли отображение данных одного клиента другому в личном кабинете? | Нет | Подтверждено жалобами: иногда показывается чужое ФИО. Причина не установлена, её должен выявить аудит. |
